# RAG 召回优化方案（2026-09-28）

## 判断依据

2026-09-28 优化前，本地聊天使用一次 LLM 问题改写、正文关键词和向量各取 30 个候选、RRF 融合后返回 5 个片段。文件名仅参与资料列表筛选，没有进入聊天召回。关键词使用全文 AND；现有合成评测的 40 个自然语言问题在该路径全部为空。512 UTF-8 字节候选分块约容纳 170 个常见汉字，需要补足命中处的上下文。

历史评测的混合 Recall@5=100%、首位命中 79/80，仅针对 40 份本用户可见的短合成文档。不能推断真实长文档、相似版本、无答案和多轮问答的质量。评测 profile 为 v1，当前新用户默认 v2。历史基线汇总在本文末尾，不能当作新策略的生产指标。

## 分期与优先级

| 阶段 | 内容 | 决策与验收 |
| --- | --- | --- |
| P0，本批 | 标题/已有 DOCX 章节标题作为独立召回路径；中文内容词部分匹配；编号和年份保持精确约束；聊天命中处补前后片段 | 复用已有索引，不调用新模型、不修改索引 profile；SQL 实测覆盖隔离、删除、标签、版本、不同维度空间；补充内容保留各自 chunk ID 与引用 |
| P1 | 真实问题评测；结合历史的追问改写；有限工具补检 | 使用 100–200 个真实问题，单独测无答案。补检只在证据缺失/跨文档任务触发，最多额外 1–2 轮；独立查询并行；无新证据或达预算停止 |
| P2 | 长文档/高频资料的文档或章节摘要索引 | 摘要作为导航，命中后回查原文；与全库原文召回并行，不能用摘要先过滤掉所有其他文档。绑定原文版本，不把生成摘要作为原始事实引用 |
| P2，按失败类型启用 | rerank、片段上下文向量化、更合适的分块 | 候选池已命中而最终前 5 未命中时试 rerank；片段语境缺失时再评估向量上下文增强。需重建的变更走现有 profile build/switch，不能原地混写 |

不全量预生成摘要，不默认对每个问题多次 LLM 检索，不把相似度/RRF 分数当作可回答概率。

## 本批实现约束

1. 关键词模式使用内容词 OR 提供候选，同时保留完整匹配优先；显式编号、版本和年份必须出现在正文或元数据中。普通问句词不触发宽泛召回。语义路径保持独立，不把关键词约束当作全库硬过滤。
2. 元数据路径检索资料标题和已存储章节标题；每份资料最多 3 个候选，在同一资料中优先明确匹配、内容匹配、向量候选，再按片段顺序选取。混合模式只把全文关键词匹配、明确标题/章节提及、元数据中的完整查询或明确字母编号视作强词法信号；先合成一份词法排名，再与语义做 RRF，避免正文和标题对同一泛词重复投票。宽松 OR/标题局部匹配用于关键词模式和显式降级，不在混合模式中挤占高质量向量结果。分数字段如实标记 `rrf`，不冒充置信度。
3. 聊天可获取每个命中片段前后各一片；仅限同 owner/item/revision/profile，使用与召回相同的知识库、类型、标签、个人事实有效期与共享权限检查。补充片段与主命中分开，不能改写主命中正文或拼造页码。
4. 外部 API 继续只返回前 top_k 个主命中；相邻上下文由内部聊天主动启用。补充内容去重，最大 10 个片段，显式保留 locator。
5. 现有索引即时受益；不更改 embedding 输入，也不自动触发已有资料重建。DOCX 之外尚未解析出来的章节标题不凭空补造。

## 成本和效果评测

同一批真实问题比较：基础检索、P0、P0+有限补检、P0+摘要、P0+rerank。记录候选 Recall@30、最终证据 Recall@5/MRR/nDCG、答案正确性/完整性、引用支持率、无答案误答率，以及 P50/P95、每问 token 和实际费用。不要用随机容量片段替代真实干扰文档。

摘要增量费用约为新增/更新文档数乘单篇处理费用；补检费用约为查询数乘补检比例乘额外轮数乘每轮费用，包含读全文/已有证据的输入 token。资料稳定且重复查询时入库增强易摊薄；大量上传少量查询时应按需生成摘要。比较费用必须同时对齐答案质量。

初始验收目标（产品目标，非已达成指标）：真实有答案问题候选召回 ≥95%，最终证据命中 ≥90%；无答案误答率 ≤5%。按问题类别单列，不以总体平均掩盖长文档或编号失败。新增元数据检索的数据库延迟需在目标硬件与真实库规模复测，历史容量数字不沿用为新版本承诺。

### 本批验证（2026-09-28）

新增 `pnpm check:knowledge:retrieval`：在已有本机 PostgreSQL 上创建随机隔离 schema，测试结束删除该 schema。使用确定性模型替身，不读取业务资料或调用付费模型。包含元数据召回、关键词容错、主命中和相邻引用、删除竞争、跨用户/集合/类型/标签隔离、外部授权和不同维度索引切换。

本批 P0 已实现。验证记录：

- 全量 Vitest 回归 1,510 项通过；融合调整后的知识/聊天相关回归 111 项通过。
- 最终隔离 PostgreSQL 回归 30 项通过（含缓存向量对照）。索引空间测试涉及共享表 DDL，测试文件按顺序执行，避免与其他文件的造数事务竞争。
- core、server、web 构建通过，web `tsc --noEmit` 通过；server 全目录 `tsc --noEmit` 仍有既有测试类型和聊天结束事件类型错误，本批检索/上下文文件无诊断，不宣称全仓类型检查通过。
- 明确文件名的反例中，目标文档原先不在向量前 5 条，加入元数据召回后排到混合检索首位；相邻片段读取中的删除竞争不会返回失效的主命中。
- 无真实付费模型调用；本批没有重测目标生产硬件延迟或真实用户问答质量。

| 冻结合成语料指标 | 优化前 | 本批 |
| --- | ---: | ---: |
| 自然语言问题，纯关键词 Recall@5 | 0/40 | 37/40 |
| 精确编号，纯关键词 Recall@5 | 40/40 | 40/40 |
| 合计，纯关键词 Recall@5 | 40/80（50%） | 77/80（96.25%） |
| 混合首位命中（复用原有真实向量缓存） | 79/80 | 79/80 |
| 混合 Recall@5（复用原有真实向量缓存） | 80/80 | 80/80 |

关键词仍未命中的三个问题为 RD-101、AC-103、DU-135。该结果只衡量 40 份合成短文档的词法检索；混合对照仅用于避免排序回归，不代表真实生产质量、长文档理解或最终答案正确性。

缓存向量对照是显式可选项，缓存不纳入 git；没有缓存时相应测试跳过，基础回归仍可复现：

```sh
pnpm check:knowledge:retrieval
RAG_QUALITY_VECTOR_CACHE=/absolute/path/to/frozen-vectors.json pnpm check:knowledge:retrieval
```

初次对照发现宽松正文、标题和语义三路等权融合会降低首位命中；已改为上述强词法信号合并策略，并加入确定性反例，防止泛词重复计票再次覆盖正确的语义命中。

### 上线与后续

本批属于读取策略变更，无数据库迁移，无 embedding profile 变化；现有资料无需重建。部署更新后的 server/web 即可启用，未替用户执行线上发布。聊天最多返回 5 个主命中及 10 个去重相邻片段；前端显示补充片段自己的出处。外部 API 的结果数量、字段白名单和授权边界保持原约定，关键词融合时 `score.kind` 可以为 `rrf`。

下一步优先补真实语料、无答案误答和目标硬件延迟评测，再实施结合历史的查询改写与有限工具补检。本批尚未接入摘要模型、rerank 或多轮工具检索。

## 历史质量与容量基线

以下为 2026-09-24、v1 profile 的原始实测，保留用于对照，不代表当前检索策略的效果或生产 SLA。

冻结数据集 `tests/eval/knowledge-v1.json`：50 份自制中文合成文档、100 个问题；40 份属于调用者，10 份属于其他用户。80 个有答案问题（含精确编号）、10 个无答案、10 个越权反例。资料均为本次测试自制，无客户隐私；不是独立人工标注的生产语料。文档 item 是相关性标注单位，Recall@5 仅统计 80 个有答案问题；引用正确性验证实际返回的 item/revision/定位，不等于 LLM 答案忠实度。

数据集 SHA-256：`20f6d3e17c96af9724dd64e5141595cf6d5d0c51556e276474c55aed36bf39f4`。评测前固定 baseline，真实 Qwen 1024 维 embedding；同一冻结语料/profile 的向量可复用，避免重复收费。

| 模式 | Recall@5 | 引用正确性 |
|---|---:|---:|
| keyword | 50% | 100% |
| semantic | 100% | 100% |

混合/向量达到 85%/95% 目标；纯关键词为对照，中文语义改写下只有 50%。越权泄漏为 0（各模式独立 404）。无答案测试单列：

- keyword：10 个问题，其中 0 个返回候选。

- hybrid：10 个问题，其中 10 个返回候选。

向量近邻有候选不代表文档中有答案；本接口是检索接口，无答案不能纳入 Recall 分母或宣称自动拒答准确率。
