# Lot Agent 产品方向与路线图

2026-10-18 整理。依据当前 main（`1379d9a`）的代码、[架构索引](agent-code-guide.md)及各专项手册。本文记录方向和优先级，不代表已实现或已验收；功能现状以代码和测试为准，阶段完成后同步更新本文。

## 1. 定位

**面向生活服务与电商小商家的营销数字员工**：从商家资料和爆款参考出发，产出合规的短视频与文案，发布后回收数据，再驱动获客与商机。

不与模型厂商及开源通用 Agent 竞争通用能力（通用研究、编码、电脑操作）。差异化来自：

- **垂直闭环**：拆解 → 文案 / 分镜 → 合规检查 → 生成 → 发布 → 数据回流，而不是单点生成工具。
- **本地化与合规**：国内与海外目标平台、广告法与平台规则、微信支付与登录。
- **私有上下文**：店铺资料、客户画像、数字分身、历史作品与效果数据，按用户隔离。
- **可靠交付**：持久化任务、计费回执、未知结果不重放、可恢复（见 [ReAct 运行与恢复](react-runtime.md)）。

## 2. 目标客群

| 客群 | 核心场景 | 现有能力 | 待补 |
| --- | --- | --- | --- |
| 线下小商铺（主力） | 探店、门店介绍、主播口播 | 营销影像三步创作、爆款拆解、合规检查 | 发布、数据回流、预计费用展示 |
| 线上店铺商家 | 商品展示、卖点讲解、主图视频 | 营销影像可用，但模板偏探店 | 「商品介绍」模板（商品图为主素材，卖点 / 价格 / 规格），电商广告用语规则 |
| 个人用户（少量） | 个人助手、轻量创作 | 通用助手、知识库、记忆、飞书、数字分身 | 见第 5 节 |

## 3. 现状与缺口

| 模块 | 现状 | 主要缺口 |
| --- | --- | --- |
| 营销影像 | 文案 / 分镜 / 合规 / Kling 分段生成 / FFmpeg 合成 / 归档已实现 | 发布禁用；实拍对口型未接入；F03 音色复用、F04 回执仅有契约；F05–F08、G01–G08 未做 |
| 参考视频分析 | 抖音、小红书、B 站；下载 / 抽帧 / OCR / ASR / 摘要 / 恢复已实现 | 生产默认关闭；三平台批量质量待验收；不支持 YouTube / Instagram |
| 数字员工 | 画像、营销资料、商机、获客 | 与营销影像未打通，不消费发布效果 |
| 知识库 | 入库、OCR、混合检索、引用、外部 API | 音视频内容识别未接入 |
| Agent 底座 | ReAct 持久化运行、白名单、技能、MCP、记忆 | `orchestration.ts` 只有 DAG 定义 / 校验，无持久化工作流执行器 |
| 发布与审核 | 通用发布连接器、云内容审核为 stub | 各平台官方开放平台接入 |
| 部署 | 单机 Docker、本地磁盘 | 对象存储、多副本、TLS 终止；生产 P95、SIGTERM 排空、Linux 隔离复核未验证 |

## 4. 平台接入

### 4.1 参考视频抓取

当前平台白名单写死在 `core/marketing-video/source.ts`、`server/marketing-analysis/source.ts`、`download.ts` 的 Cookie 域名校验和 `routes.ts` 的 `/capabilities`。底层 yt-dlp 本身支持 YouTube / Instagram，代码层改动有限：

1. 识别 YouTube `watch` / `youtu.be` / `/shorts/` 与 Instagram `/reel/` / `/p/`，前后端同步并补单测。
2. 扩展 Cookie 域名白名单、能力接口和前端文案；超过 180 秒的长视频截取或拒绝。

真正的约束：

- **网络**：国内部署的媒体 Worker 无法访问。`egress.ts` 解析后直连公网 IP，不支持上游代理。优先单独部署海外媒体分析 Worker；改为上游代理需重新评审 SSRF 与出口策略。
- **反爬**：YouTube 对机房 IP 常要求登录验证；Instagram Reels 多数需登录且限流严格。可复用用户自带加密 Cookie 机制，需提示账号风险。
- **语言**：英语 / 印尼语的 Qwen ASR、OCR 与文案质量需实测，输出语言与 `globle` 多语言开关联动。

顺序：YouTube Shorts（海外 Worker + 可选 Cookie，10–20 条真实样本验收）→ Instagram。

### 4.2 发布

统一抽象为「发布连接器 + 持久化发布任务」：复用营销项目与发布元数据，校验平台授权，记录外部回执；打开平台网页不视为发布成功，未知结果只核实不重发。

| 平台 | 前置条件（需提前申请，与开发并行） |
| --- | --- |
| 抖音 | 开放平台企业资质与权限审核 |
| 小红书 | 开放平台资质与权限审核 |
| YouTube | Data API 应用审核；通过前上传只能为私有视频；注意配额 |
| Instagram | 商家 / 创作者账号绑定 Facebook 主页，Graph API 内容发布权限审核 |

## 5. 通用助手转为个人助手

- 面向单个用户开放，围绕「懂我和我的生意」：记忆、个人知识库、数字分身、店铺与客户资料。
- 触达优先走用户常用渠道：飞书已接入，后续评估微信 / 小程序消息。
- 不做通用深度研究、编码、电脑操作等与领先通用 Agent 正面竞争的方向；桌面本机工具维持现状。
- 模型凭证、记忆、计费已按用户隔离，单用户使用无需改架构。

## 6. 数据信任

个人商家不愿提供真实营销数据，主要顾虑是数据被挪用（训练、给同行、被平台看到）、账号受损、交出后无法收回。原则：先给价值，数据由商家逐步自主放开。

### 6.1 零数据可用，分级授权

不提供真实数据也能完成首条视频（公开爆款拆解、公开门店信息、手填卖点）；接入数据作为可选增强，由商家看到效果后自行决定。

| 级别 | 数据 | 用途 | 默认 |
| --- | --- | --- | --- |
| L0 | 公开信息（门店名、公开视频） | 拆解、文案 | 开 |
| L1 | 商家填写的店铺与产品资料 | 文案准确性 | 开 |
| L2 | 发布效果数据（只读、聚合指标） | 效果复盘、下一轮优化 | 关，需授权 |
| L3 | 客户数据 | 画像、获客 | 关，需授权 |

- 发布与数据回流只走平台官方 OAuth，只申请只读、最小范围，商家可在平台侧撤销；不收集账号密码。参考视频抓取现有的用户自带 Cookie 机制信任成本高，仅作为可选兜底并提示账号风险。
- 能用聚合指标（播放、完播、到店转化）就不取原始明细。

### 6.2 脱敏与本地处理

- 客户名单上传前去除手机号、姓名等标识，只保留标签（年龄段、消费频次）。
- 桌面端可在本地工作目录完成脱敏，仅上传结果。

### 6.3 可见、可控、可删

- 生成结果标明使用了哪些资料（延续知识库引用），并提供「本次不使用私有数据」开关。
- 「我的数据」页面：查看存储内容与授权，一键导出、删除、撤销平台授权；保存期限可选，延续参考视频原片 7 天回收的做法。
- 当前代码只有注销相关文案，未见完整的账号注销与数据导出入口，需补齐。

### 6.4 承诺与合规

- 隐私政策（`web/components/LegalModal.tsx`）目前承诺文字输入不用于训练，需扩展到上传资料与视频。
- 核对上游模型及网关服务商的训练与留存条款，确保整条链路可兑现承诺。
- 明确数据境内存储、遵守《个人信息保护法》、商家间数据隔离；对连锁商家准备数据处理协议。

### 6.5 借助信任渠道

通过代运营 / 本地服务商代为操作降低信任门槛；用试点商家的真实效果案例证明数据接入的价值。

## 7. 路线图

### P0 收敛与上线

- 按 [十月十六日实施记录](marketing-video-implementation-20261016.md#发布门禁与回滚交接) 的门禁完成生产发布与验收：三平台批量拆解质量、SIGTERM 排空、Linux 隔离复核、真实成片质量门槛（产品负责人定标准），通过后在生产开启参考视频分析。
- 营销影像预计费用展示。
- 提交各发布平台开放平台资质申请。
- 修正 [部署手册](deployment.md) 中「异步生成为 Stub」及「后续演进」的过时描述。

### P1 打通闭环

- 抖音、小红书发布连接器（官方 OAuth，只读与发布最小权限）。
- 「我的数据」页面：查看、导出、删除、撤销授权，补齐账号注销；生成结果标明数据来源并支持不使用私有数据。
- 隐私政策扩展到上传资料与视频，核对上游服务商数据条款。
- 「商品介绍」模板与电商合规规则，服务线上店铺商家。
- F03 同父任务音色复用、F04 审核与发布文案回执（契约与样例已就绪）。
- YouTube Shorts 参考视频抓取（海外媒体 Worker）。

### P2 回流与平台化

- YouTube、Instagram 发布；Instagram 抓取。
- 发布效果数据回流：写入知识库，供下一轮拆解 / 文案参考，并驱动数字员工画像与获客。
- 个人助手渠道扩展。
- 持久化工作流执行器，将营销影像链路模板化，以便扩展团购图文、直播脚本等场景。
- 知识库音视频识别，复用参考视频分析的解码、OCR、ASR 链路。
- 对象存储、多副本、TLS 终止、Redis 限流。

### 维持现状

办公类（文档、PPT、合同对比）、小程序（查看、分享、轻量生成）、桌面本机工具；实拍对口型在发布闭环验证后再评估。

## 8. 验证方式与风险

- **验证**：每个阶段先找 10–20 家真实商家试用，关注每周实际发布条数、续费与留存，而不是功能数量。
- **平台方竞争**：短视频平台与模型厂商自带创作工具持续增强，单点生成没有壁垒；坚持闭环、合规、私有数据与服务交付。
- **获客成本**：小商家付费意愿低、流失高，优先评估本地服务商 / 代运营渠道合作。
- **数据信任**：商家拒绝授权会削弱数据回流与获客能力；产品须在零数据下仍有价值，见第 6 节。
- **范围过宽**：模块已多，新增方向须先说明对上述闭环的贡献。
