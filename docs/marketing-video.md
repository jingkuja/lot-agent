# 营销视频制作

## 首版范围

营销影像入口提供「确定文案 → 确定素材 → 配音与字幕」。第一步生成文案时同时生成完整分镜；「拆解爆款文案」按钮下直接粘贴视频链接或文案，产品补充要求选填。视频分析在后台完成并自动写回草稿，资料折叠查看，无需选择文字/证据或预览应用。该创作流程不设本地金额预算，由上游余额决定是否继续；预计费用展示暂未加入。最后点击「确认分镜并生成视频」才提交制作任务。没有详细分镜的旧草稿仍可生成分镜或手动编排。


数字人路径复用 Kling 原生视频配音，支持已有肖像 / 音色库和背景参考图；不承诺逐字播报、音色跨段一致或精确口型。实拍对口型尚未接入，入口禁用。BGM 为用户上传的音频，在本地混入；字幕由视频模型按每段提示词生成，要求与该段旁白文字、语言和节奏一致；不使用本地 SRT 或 FFmpeg 字幕滤镜。生成前可关闭字幕，发布前需试听和校对。

整片时长可按整数秒选择 **15–60 秒**。`kimi-k3` 根据内容选择镜数和节奏，每镜 **4–15 秒**，总长允许落在目标时长至目标 +5 秒之间，最长 **65 秒**，不强制额外加时。例如选择 60 秒可生成 62–65 秒；每片最多 15 镜。生成仍最多并发 2 个片段。AI 已给出容差范围内的时长时保持其分配；超出范围时在口播最低时长与单镜上限内按建议节奏重新分配整数秒。时长在付费生成前确定：API 和预留事务校验完整分镜，Worker 在调用任何视频提供器前再次校验持久化总长；例如 5 ×13 秒直接请求 65 秒，70 秒配置不会调用视频模型。FFmpeg 不承担将超额付费时长裁至 65 秒的策略。所选目标与实际分镜总长分开显示；合并、成片校验及产物时长都采用各镜时长之和，不把额外内容裁掉。

数字人模式要求每镜都有人物正面出镜，可辨认脸部及上半身；产品细节与人物同框。选择肖像时使用该肖像身份，未选肖像时安排同一人物。该约束同时进入文案/分镜创作、分镜修改和实际视频请求；后选肖像也生效。模型成片的出镜和身份一致性仍需实际预览验证。

画面支持 9:16、16:9、1:1，清晰度支持 720p、1080p。先规范化片段的尺寸、帧率、音轨和编码，再顺序拼接；检查片段有音轨和足够时长，最终时长允许 AAC 封装带来的微小误差。

## 提示词与素材引用

`server/marketing-video/creation.ts` 统一文案创作、分镜修改和发布标题提示词；`prompt.ts` 统一分镜字段职责、时长约束、素材上下文及实际视频提示词。文案与分镜创作是纯文字请求，只接收已选素材的角色和数量，不宣称已经看过上传图片或听过音色样例。参考视频拆解另由分析链路提供可见内容、ASR 状态与采样缺口，不能把结构推测当作产品事实，也不能将未获得转写解释为原片无声。

| 内容 | 用途与边界 |
| --- | --- |
| 主题 / 创作要求 | 提供产品事实、顾客、语气和节奏。改写时仅调整风格仍保留参考中有依据的事实；明确换产品时不得迁移原产品价格、优惠、资质或效果。切回智能生成后不发送残留的改写来源。 |
| 口播 `script` | 每镜最终文案，顺序拼接为正文。修改画面、动作或镜头默认保持原文、原语言和顺序；只有明确要求改文案才改写。标题、标签、分析及素材名称不进入口播。 |
| `visual / action / camera` | 分别描述画面构成、可执行动作、景别和主要镜头运动，每镜填写完整。每个片段独立生成，需要写明一致的人物和产品风格；允许分镜有意切换场景。 |
| 拆解来源 | `reference`、`referenceUpload` 及分析证据只用于文案和结构参考，不自动进入视频生成。 |
| 肖像、背景、场景图片 | 按「肖像 → 背景 → 场景」及各组内顺序提交。肖像第一张为主身份，其余仅补充同一人；背景限定环境布局，场景参考相关构图与物品细节，不将其他人物替换为主角，也不强制拼贴所有参考。 |
| 生成参考视频 | 仅 `assets.video` 直接参与生成，用于动作与构图，不复制原片台词、字幕或音乐。当前模式关闭原生口播，分镜按无声演示设计；开启字幕时显示该镜文案，关闭时通过画面动作表达。 |
| 音色、BGM、封面 | 音色只提供声音身份，朗读当前文案而非样例台词；Kling 使用准备好的自定义音色，不把它称作未提交的 `audio 1`。BGM 在合成时混入，封面不计入分镜图片编号。 |

可编辑分镜按素材角色描述，不固化全局 `image N` 编号；最终 `marketingImageReferences` 同时用于请求图片列表和提示词编号，避免后补素材导致引用错位。当前比例、配音 / 字幕开关、素材角色约束优先于旧分镜中的冲突描述；选定背景 / 场景参考优先于不兼容的泛化背景文字，肖像身份优先于其他素材中的人物。单镜生成只带当前镜文案及画面、动作、镜头信息，保留素材原有标识，不额外生成水印、品牌标识或发布标题。上述为模型约束，素材还原、跨段一致性和字幕效果仍需以成片验证。

实际视频提示词使用精简规则，保留完整的已确认内容。[TokenHub Kling 调用指南](https://cloud.tencent.com/document/product/1823/135742)给出的 V3 Omni 提示词建议长度为 2500 字符、上限为 3072 字符；API 首次提交及 Worker 所有待提交片段在任何视频 / 音色调用前检查上限，超长时提示精简描述，不截断文案或分镜。已取得外部任务 ID 的片段继续查询原任务，不以新提示词校验阻止下载恢复。

## 分镜确认与修改

每个分镜保存独立 `durationSec`，包含累计时间范围、口播、画面内容、人物 / 产品动作和景别 / 镜头运动。可直接手动编辑，也可输入要求让 AI 修改全部分镜或指定一镜；还可选择「手动编排分镜」跳过首次 AI 请求。文案生成、发布文案与分镜生成/修改固定使用 `kimi-k3` 和当前用户凭证，不会创建视频任务。只有点击「确认分镜并生成视频」才提交视频生成。

分镜时长保存在现有草稿 JSONB 中；迁移 41 将片段槽位从 0–3 扩展到 0–14。旧分镜缺少时长时按原有 15 秒读取，已提交任务恢复使用持久化的原分段。手动改口播同步正文；修改正文后清空旧分镜；修改整片时长优先自动重分配当前各镜时长，无法容纳时清空分镜供 AI 重新编排，避免过期内容被提交。服务端验证每镜 4–15 秒、各镜时长总和须在目标到目标 +5 秒范围内且不超过 65 秒、对应时长的口播预算、必填描述与正文一致性，画面 / 动作 / 镜头修改也会使原风险检查失效。AI 输出通过完整性及结构校验后按草稿版本保存，失败保留原分镜，并发版本冲突不覆盖其他页面的修改。

任务快照包含确认后的完整分镜；片段口播按用户编辑后的边界保存，Worker 为每段添加对应的画面、动作和镜头提示词。结果页展示制作分镜；修改已提交的分镜会复制为新草稿，重新制作会产生新的生成费用。旧草稿和任务继续兼容，未保存详细分镜的旧成片会明确提示。

## 存储与恢复

文案创作和分镜修改使用 `marketing_text_operations`（迁移 42）：前端先保存草稿，再携带 `clientRequestId` 和版本发起请求。服务端先保存调用意图，保存上游回执，再原子保存结果并尝试按版本回填；冲突结果仍可在“保存的创作记录”查看。相同请求 ID 和输入只返回原记录，不再次调用模型；不同输入复用 ID 返回 409。进程中断或未知回执阻止该草稿再次创作，需管理员核对上游回执后处理，不能直接清除记录绕过保护。记录查询接口为 `GET /api/marketing-videos/:id/text-operations`，由服务端校验归属。

`POST /api/marketing-videos/copy` 需要 `projectId`、`version`、`clientRequestId`、`draft`、`locale` 和 `source: {kind: "text" | "video"}`；省略 source 的旧客户端使用共享识别规则，视频类型返回 `VIDEO_ANALYSIS_REQUIRED`，必须通过参考视频分析入口。`POST /:id/storyboard` 在原参数基础上增加 `clientRequestId`。缺少请求 ID 的旧客户端会被拒绝，不回退到不持久化的付费路径；部署时同步更新 Web 和 API。


- `core/marketing-video` 保存共享 schema、口播长度估算、分段规划和存储接口。
- `/api/marketing-videos` 为独立项目 API，沿用会话登录和用户凭证；文案/分镜初次创作由上游处理余额，其他制作请求保留既有额度检查。模型固定在服务端；输入素材只接受当前用户资产 ID，不接受客户端任意 URL。新项目不创建聊天会话，旧会话结果继续可读。
- 迁移 36 增加 `marketing_video_projects`、`marketing_video_segments` 和 `usage_logs.idempotency_key`。草稿版本防止多页面覆盖；提交后制作配置固定，标题标签仍可修改。数据库 JSONB 比较须经过 schema 规范化，不能直接依赖键顺序。
- 草稿自动保存；浏览器仅按用户 ID 保存最后打开的项目 ID。项目列表显示最近 50 条。断开页面不取消后台任务。
- PG 事务先持久化父任务、全部片段和不可变参数，再向 BullMQ 投递父任务 ID。Redis 故障后可在结果页点「恢复排队任务」。不会自动重试付费提交。
- Worker 持有父任务 advisory lock，最多并行执行两个片段。成功片段继续复用；已取得模型任务 ID 的片段继续查询 / 下载。模型明确失败或产物缺少音轨、时长不足时，用户点击继续才创建新生成请求。
- 在模型 POST 前记录提交未知标记。收到任务 ID 后立即保存；未收到回执时，保留未知状态并停止再次 POST。此时需人工核实网关记录，不能直接清空标记当作失败重发。
- 片段资产与恢复输出同一事务提交；计量用用户、片段、模型任务 ID 去重，避免工作进程重启造成重复计量。重新生成失败片段可能产生供应商费用。纯查询、下载和拼接恢复不做新增额度预检。
- 取消会传递到片段轮询、下载和 FFmpeg；第三方已接受的请求不保证可撤销或退费。原 Worker 收尾期间不允许重新激活父任务。
- 入库将视频原件、口播、发布标题、话题标签和项目 ID 保存在私有知识库。重复入库复用资料；修改标题标签后可点「更新知识库草稿」。删除过的归档可重新创建。需要 `KNOWLEDGE_MANAGEMENT_ENABLED=1`；可选索引仍遵循既有知识 Worker 开关。

首版尚无真实抖音授权和发布接口。结果页提供下载视频、复制标题标签，直发按钮明确禁用。接入后应复用持久化项目和发布元数据，另建发布任务并校验平台授权，不能把打开抖音网页视为发布成功。

## 环境和验证

先由 API 执行迁移，再启动 Worker。API 和普通视频 Worker 均需要 `ffmpeg`、`ffprobe`；编码需要 libx264、AAC；模型字幕不依赖 libass 或本地字幕字体。可用 `MARKETING_FFMPEG_PATH` / `MARKETING_FFPROBE_PATH` 指定程序路径。容器配置参见 [部署](deployment.md)。拼接能力检查失败时界面阻止生成；字幕选项仅控制模型提示词，不参与本地能力检查。

音色样例继续使用 `KLING_VOICE_BASE_URL` / `KLING_VOICE_API_KEY`，视频推理仍使用当前用户模型凭证；素材引用需要正确的 `PUBLIC_BASE_URL`。未选择音色样例时使用模型原生旁白。

页面先检查草稿列表和服务能力，成功后才启用编辑、自动保存和生成；接口未部署返回 404 时显示更新服务提示，连接失败可点「重新连接」。普通本地开发代理连接 `localhost:3000`，仅桌面开发模式跟随桌面服务器设置。线上升级必须同时更新 Web、API 和 Worker 镜像并执行迁移至 43；只更新 Web 会导致新接口 `Not Found`。文案和分镜生成后自动保存；风险检查可按需执行，提交制作前仍会自动检查当前内容。

```bash
pnpm --filter @lot-agent/core build
pnpm exec vitest run packages/core/src/marketing-video packages/server/src/marketing-video packages/server/src/jobs/bullmq-queue.test.ts packages/server/src/billing/meter.test.ts packages/server/src/generation/run-job.test.ts
pnpm check:marketing-video:ui
# 指向空的本地 marketing_check_* 数据库；脚本拒绝非空库，不清理已有表。
MARKETING_CHECK_DATABASE_URL=postgresql://USER:PASSWORD@127.0.0.1:5432/marketing_check_local pnpm check:marketing-video:db
pnpm --filter @lot-agent/server build
pnpm --filter @lot-agent/web build
```

数据库脚本只使用模拟模型和本地合成素材，验证升级迁移、归属、并发预留、版本检查、失败续作、未知提交保护、取消、下载恢复、计量去重和知识库更新 / 重建，并实际拼接 15 / 17 / 30 / 45 / 60 秒视频和 BGM，以及目标 60 秒、实际 65 秒的视频。字幕提示词及无本地字幕能力时的提交由单元测试和浏览器脚本覆盖；模型字幕实际效果需真实生成后校对。浏览器脚本使用模拟接口，可通过 `PLAYWRIGHT_MODULE` 指定 Playwright，`MARKETING_SCREENSHOTS_DIR` 保存截图。上述结果不替代真实模型音画质量或抖音发布验收。

文案生成、审核、标题和分镜 AI 修改使用 `marketing-video/text.ts`：请求 JSON 模式和最多 8192 输出 token，固定选择 `kimi-k3`，保留模型默认推理设置，不发送该模型不支持的 `reasoning.effort=none`；300 秒超时并传递请求取消。必须收到正常完成标记后才解析 JSON；空结果、截断、格式异常均不能写入审核结果，也不会自动重新采样。已知模型用量包含失败回执并记录一次。错误按授权、额度、连接和输出完整性返回安全提示与错误码，日志不记录文案、模型思考、原始响应或凭证。

## 后续对口型服务候选

| 服务 | 对本项目的用途与限制 |
| --- | --- |
| [腾讯云智能数智人：视频免训练](https://cloud.tencent.com/document/product/1240/116222) / [照片免训练](https://cloud.tencent.com/document/product/1240/118475) | 优先评估需要同时覆盖实拍与数字人的方案。视频和照片都有文本 / 音频驱动接口；照片音频驱动支持 2–60 秒，输出 720p / 1080p。视频接口需购买小时包或并发资源；应先用同一文案和素材对比实际效果。 |
| [阿里云 VideoRetalk](https://help.aliyun.com/en/model-studio/videoretalk-api) | 适合先补实拍口型替换。输入人物视频及完整人声音频；视频 / 音频均支持 2–120 秒，可覆盖本项目长度。北京地域，需单独接入完整 TTS 音轨；现有 Kling 参考音色不等同于输出的配音文件。 |
| [阿里云 wan2.2-s2v](https://help.aliyun.com/zh/model-studio/wan-s2v-api) | 照片 + 音频驱动的另一选择，480p / 720p；单段音频须小于 20 秒，仍需复用本项目的分段和拼接。 |

建议先评测腾讯两类免训练接口是否能统一满足素材路径；若只补实拍口型，优先小规模评测 VideoRetalk。后续链路应先生成完整 TTS 音频，再以音频驱动人物并获得字幕时间轴，最后混 BGM；这会比当前模型原生配音更便于控制文案和字幕。
