# 营销视频制作

## 首版范围

营销影像入口提供「确定文案 → 确定素材 → 确认与制作」。第一步生成文案时同时生成完整分镜；「拆解爆款文案」按钮下直接粘贴视频链接或文案，产品补充要求选填。视频分析在后台完成并自动写回草稿，资料折叠查看，无需选择文字/证据或预览应用。该创作流程不设本地金额预算，由上游余额决定是否继续；预计费用展示暂未加入。最后点击「确认分镜并生成视频」才提交制作任务。没有详细分镜的旧草稿仍可生成分镜或手动编排。


片段模型由服务端 `MARKETING_VIDEO_MODEL` 选择（默认 `grok-imagine-video-1.5`，可选 `kling-video-v3-omni`），经统一 `/videos` 接口由网关适配。见下方[模型配置与切换](#模型配置与切换)。数字人路径复用模型原生视频配音，支持已有肖像 / 音色库和背景参考图；不承诺逐字播报、音色跨段一致或精确口型。实拍对口型尚未接入：草稿只有数字人模式，旧草稿中的 `recorded` 按数字人读取。BGM 为用户上传的音频，在本地混入；字幕由视频模型按每段提示词生成，要求与该段旁白文字、语言和节奏一致；不使用本地 SRT 或 FFmpeg 字幕滤镜。生成前可关闭字幕，发布前需试听和校对。

整片时长可按整数秒选择 **15–60 秒**。`kimi-k3` 根据内容选择镜数和节奏，每镜 **4–15 秒**，总长允许落在目标时长至目标 +5 秒之间，最长 **65 秒**，不强制额外加时。例如选择 60 秒可生成 62–65 秒；每片最多 15 镜。每条视频同时提交的片段数由 `MARKETING_VIDEO_SEGMENT_CONCURRENCY` 配置（默认 2）。AI 已给出容差范围内的时长时保持其分配；超出范围时在口播最低时长与单镜上限内按建议节奏重新分配整数秒。时长在付费生成前确定：API 和预留事务校验完整分镜，Worker 在调用任何视频提供器前再次校验持久化总长；例如 5 ×13 秒直接请求 65 秒，70 秒配置不会调用视频模型。FFmpeg 不承担将超额付费时长裁至 65 秒的策略。所选目标与实际分镜总长分开显示；合并、成片校验及产物时长都采用各镜时长之和，不把额外内容裁掉。

第一步「人物出镜」可选（草稿字段 `presenter`，旧草稿与冻结任务缺省为 `always`）：「主播全程出镜」（`always`）要求每镜都有人物正面出镜，可辨认脸部及上半身，产品细节与人物同框，适合主播宣传；「混合镜头」（`mixed`）要求主播至少出现在一个镜头（优先开场），其余镜头可拍环境、菜品和产品特写，由分镜画面写明是否出镜，无人物的镜头以画外旁白朗读台词，适合探店。选择肖像时人物出镜处使用该肖像身份，未选肖像时安排同一人物。该约束同时进入文案/分镜创作、分镜修改和实际视频请求（`prompt.ts → marketingPresenterRequirement`）；后选肖像或切换出镜方式也生效，切换后建议重新生成分镜。模型成片的出镜和身份一致性仍需实际预览验证。

画面支持 9:16、16:9、1:1，清晰度支持 720p、1080p；所选模型限制参考素材清晰度时（Grok：使用图片或参考视频最高 720p），前后端均拒绝 1080p。先规范化片段的尺寸、帧率、音轨和编码，再顺序拼接；检查片段有音轨和足够时长，最终时长允许 AAC 封装带来的微小误差。

## 模型配置与切换

`core/marketing-video/models.ts` 为每个片段模型定义一份 `MarketingVideoProfile`，草稿、分镜、提交和恢复只读取配置，不写死模型：

| 字段 | 含义 | Kling V3 Omni | Grok Imagine 1.5 |
| --- | --- | --- | --- |
| `shotMaxSeconds` / `referenceVideoShotMaxSeconds` | 每镜上限（无 / 有参考视频） | 15 / 15 | 15 / 8 |
| `imagesWithReferenceVideo` | 选参考视频后可同用的人物与场景图片数；0 表示模型不使用图片，须二选一 | 3 | 0 |
| `referenceMaxQuality` | 使用图片或参考视频时的最高清晰度 | 不限 | 720p |
| `referenceVideo` | 参考视频时长、帧率、宽高、像素、宽高比限制 | 3–15.5 秒等官方限制 | 未公布，仅检查可读画面 |
| `promptMaxChars` | 单镜提示词上限 | 3072 | 3072 |
| `referenceImage` | 人物 / 背景 / 场景参考图格式、大小与尺寸 | JPG/PNG，≤50 MB，短边 ≥300 px，宽高比 1:2.5–2.5:1 | JPG/PNG/WebP，≤20 MB；[参考图文档](https://docs.x.ai/developers/model-capabilities/video/reference-to-video)只公布数量，不另设尺寸限制 |

- 切换：服务端设置 `MARKETING_VIDEO_MODEL=<modelId>`，`marketing-video/model.ts` 启动时校验，未知 ID 直接报错。`GET /api/marketing-videos/capabilities` 返回当前配置的 `model`，前端据此校验并生成提示文案，无需重新构建。参考图上传前由前端按当前配置的 `referenceImage` 检查（`marketingReferenceImageIssue`，前后端共用）；`POST /:id/generate` 在新提交前再按当前模型读取每张参考图的真实文件头（`image-size.ts`，格式取自文件签名而非上传声明的 MIME）检查格式、大小和宽高，因此切换模型后已选的素材也会重检。Kling 的参考视频上传前检查仍由前端按模型 ID 选择。
- 冻结任务：新任务的 `input.modelId` 记录提交时的模型，`marketingInputVersion: 3`。恢复时 `marketingJobProfile` 按记录的 `modelId` 取配置（缺少时视为 Kling），版本 1 的输入不做参考素材检查。已有任务可能引用的配置不可删除。
- 新增模型（如 Seedance）：在 `models.ts` 增加配置并加入 `MARKETING_VIDEO_PROFILES`。若模型需要配置以外的行为（如 Seedance 提示词需按 `@Image1` 引用素材、带参考视频时时长与比例自适应），再给配置加字段，并在 `prompt.ts` / 路由中按字段分支，不按模型名写死。

## 提示词与素材引用

`server/marketing-video/creation.ts` 统一文案创作、分镜修改和发布标题提示词；`prompt.ts` 统一分镜字段职责、时长约束、素材上下文及实际视频提示词。文案与分镜创作是纯文字请求，只接收已选素材的角色和数量，不宣称已经看过上传图片或听过音色样例。参考视频拆解另由分析链路提供可见内容、ASR 状态与采样缺口，不能把结构推测当作产品事实，也不能将未获得转写解释为原片无声。

| 内容 | 用途与边界 |
| --- | --- |
| 主题 / 创作要求 | 提供产品事实、顾客、语气和节奏。改写时仅调整风格仍保留参考中有依据的事实；明确换产品时不得迁移原产品价格、优惠、资质或效果。切回智能生成后不发送残留的改写来源。 |
| 口播 `script` | 每镜最终文案，顺序拼接为正文。修改画面、动作或镜头默认保持原文、原语言和顺序；只有明确要求改文案才改写。标题、标签、分析及素材名称不进入口播。 |
| `visual / action / camera` | 分别描述画面构成、可执行动作、景别和主要镜头运动，每镜填写完整。只写本镜新增的主体、产品和构图，不与统一设定冲突；只有画面明确写出其他地点时才换场景。 |
| 统一人物与场景设定 `continuity` | 每个片段独立生成、互相看不到，跨镜一致只能靠这段共享描述：人物年龄感、发型发色、妆容、服装颜色材质与配饰，主场景类型、布局、关键道具与配色，光线方向与色温，整体色调。文案创作与整板分镜修改时由 AI 写出（建议 ≤300 字，上限 400），单镜修改保持不变；用户可在分镜上方编辑，提交后冻结。每个视频请求在 `confirmedShot` 中原样携带，并要求人物、服装、场景、光线与之严格一致；选了肖像时只描述服装造型，脸部以肖像为准，并要求忠实还原脸型、五官、肤色和年龄感；选了背景 / 场景图时场景细节由图片决定。为空（手动编排或旧草稿）时退回 `backgroundDescription`，要求各镜布局、道具、光线和配色一致。非空时纳入内容检查。仍是模型约束，跨镜一致性需以成片验证。 |
| 拆解来源 | `reference`、`referenceUpload` 及分析证据只用于文案和结构参考，不自动进入视频生成。 |
| 肖像、背景、场景图片 | 按「肖像 → 背景 → 场景」及各组内顺序提交。肖像第一张为主身份，其余仅补充同一人；背景限定环境布局，场景参考相关构图与物品细节，不将其他人物替换为主角，也不强制拼贴所有参考。 |
| 生成参考视频 | 仅 `assets.video` 直接参与生成，用于动作与构图，不复制原片台词、字幕或音乐。当前模式关闭原生口播，分镜按无声演示设计；开启字幕时显示该镜文案，关闭时通过画面动作表达。 |
| 音色、BGM、封面 | 音色只提供声音身份，朗读当前文案而非样例台词；Kling 使用准备好的自定义音色（`run-job.ts` 按模型 ID 自动走音色链路），其他模型直接提交音频链接；不把它称作未提交的 `audio 1`。Kling 音色按父任务和样例槽位只创建一次：`run.ts` 在片段并发前以父任务 ID 准备音色，各片段经 `RunJobDeps.voiceScopeTaskId` 复用同一检查点；已有子片段级检查点的旧任务继续按子片段查询原请求。BGM 在合成时混入。旧草稿的封面槽位从未参与生成，读取时丢弃。 |

可编辑分镜按素材角色描述，不固化全局 `image N` 编号；最终 `marketingImageReferences` 同时用于请求图片列表和提示词编号，避免后补素材导致引用错位。当前比例、配音 / 字幕开关、素材角色约束优先于旧分镜中的冲突描述；选定背景 / 场景参考优先于不兼容的泛化背景文字，肖像身份优先于其他素材中的人物。单镜生成只带当前镜文案及画面、动作、镜头信息，保留素材原有标识，不额外生成水印、品牌标识或发布标题。上述为模型约束，素材还原、跨段一致性和字幕效果仍需以成片验证。

实际视频提示词使用精简规则，保留完整的已确认内容。提示词上限取模型配置的 `promptMaxChars`（Kling 依据 [TokenHub 调用指南](https://cloud.tencent.com/document/product/1823/135742) 为 3072 字符；[Grok 视频文档](https://docs.x.ai/developers/model-capabilities/video/generation)未给出数值上限，沿用 3072）；API 首次提交及 Worker 所有待提交片段在任何视频 / 音色调用前检查上限，超长时提示精简描述，不截断文案或分镜。已取得外部任务 ID 的片段继续查询原任务，不以新提示词校验阻止下载恢复。

## 分镜确认与修改

每个分镜保存独立 `durationSec`，包含累计时间范围、口播、画面内容、人物 / 产品动作和景别 / 镜头运动。可直接手动编辑，也可输入要求让 AI 修改全部分镜或指定一镜；还可选择「手动编排分镜」跳过首次 AI 请求。文案生成、发布文案与分镜生成/修改固定使用 `kimi-k3` 和当前用户凭证，不会创建视频任务。只有点击「确认分镜并生成视频」才提交视频生成。

分镜时长保存在现有草稿 JSONB 中；迁移 41 将片段槽位从 0–3 扩展到 0–14。旧分镜缺少时长时按原有 15 秒读取，已提交任务恢复使用持久化的原分段。手动改口播同步正文；修改正文后清空旧分镜；修改整片时长优先自动重分配当前各镜时长，无法容纳时清空分镜供 AI 重新编排，避免过期内容被提交。服务端验证每镜 4–15 秒、各镜时长总和须在目标到目标 +5 秒范围内且不超过 65 秒、对应时长的口播预算、必填描述与正文一致性，画面 / 动作 / 镜头修改也会使原风险检查失效。AI 输出通过完整性及结构校验后按草稿版本保存，失败保留原分镜，并发版本冲突不覆盖其他页面的修改。

第 3 步「确认与制作」只显示分镜总览（每镜时间段与画面）和目标时长 / 分段统计，展开「修改分镜」后编辑；在本步刚生成的分镜自动展开。

草稿字段 `storyboardAudio` 记录整板分镜是按有声口播（`true`）还是无声展示（`false`，选了生成参考视频）规划的：文案创作与整板分镜修改由服务端按当时的 `assets.video` 写入，单镜修改保持原值，「手动编排分镜」由前端写入；旧分镜没有该字段，添加或移除参考视频时前端按切换前的状态补记。`marketingStoryboardAudioMismatch` 判断分镜与当前设置不一致时，第 2 步参考视频区和第 3 步分镜总览显示提示，提供「按无声展示 / 按口播重新生成分镜」（整板 AI 修改，保持镜数与每镜时长）和「保留当前分镜」（把记录改为当前设置）；仍不一致时点击生成会先弹出确认。字段存放在草稿 JSONB 中，无需迁移，不进入片段提示词。

任务快照包含确认后的完整分镜；片段口播按用户编辑后的边界保存，Worker 为每段添加对应的画面、动作和镜头提示词。结果页展示制作分镜；修改已提交的分镜会复制为新草稿，重新制作会产生新的生成费用。旧草稿和任务继续兼容，未保存详细分镜的旧成片会明确提示。

## 存储与恢复

文案创作和分镜修改使用 `marketing_text_operations`（迁移 42）：前端先保存草稿，再携带 `clientRequestId` 和版本发起请求。服务端先保存调用意图，保存上游回执，再原子保存结果并尝试按版本回填；冲突结果保留在服务端记录中，不回填草稿。相同请求 ID 和输入只返回原记录，不再次调用模型；不同输入复用 ID 返回 409。模型请求不随浏览器断开而中止：刷新或关闭页面后请求继续执行（仍受 300 秒期限约束），结果照常保存并回填，回到页面后自动显示；已收到完整回执的结果由前端自动恢复填入草稿（`POST /:id/text-operations/:operationId/recover`，只解析已保存回执，不调用模型）。进程中断或超时等未知回执阻止该草稿再次创作；正在执行的请求（未超过 360 秒）不能放弃。用户可确认“可能重复计费”后点击「放弃这次结果」（`POST /:id/text-operations/:operationId/release`，迁移 49）：记录改为 `released` 并写入 `released_at`，回执保留供核对，迟到的结果不再回填；已收到完整回执的记录只能恢复，不能放弃。记录查询结果带 `createdAt`；进行中的请求在页面顶部显示阶段和已用时，本页发起的文案、分镜、检查和标题请求在底部停靠区显示同样信息并说明最长 5 分钟。记录查询接口为 `GET /api/marketing-videos/:id/text-operations`，由服务端校验归属。

`POST /api/marketing-videos/copy` 需要 `projectId`、`version`、`clientRequestId`、`draft`、`locale` 和 `source: {kind: "text" | "video"}`；省略 source 的旧客户端使用共享识别规则，视频类型返回 `VIDEO_ANALYSIS_REQUIRED`，必须通过参考视频分析入口。`POST /:id/storyboard` 在原参数基础上增加 `clientRequestId`。缺少请求 ID 的旧客户端会被拒绝，不回退到不持久化的付费路径；部署时同步更新 Web 和 API。

内容检查（`POST /:id/review`）和标题标签（`POST /:id/publication`）同样写入 `marketing_text_operations`（迁移 50 增加 `review` / `publication` 两种 kind），请求需带 `clientRequestId` 和 `version`。输入快照冻结请求时的草稿：审核结果只在项目版本未变时写入 `review / reviewed_script`，版本已变则记为 `conflict` 并返回 409；标题标签的“只补缺失项”基于冻结草稿计算，按版本条件原子写回。审核解析器版本包含规则版本（`marketing-review-v1:<MARKETING_REVIEW_RULE_VERSION>`），规则升级后旧回执不能再恢复，只能放弃。标题标签在视频提交后仍可生成；文案和分镜仍只允许提交前修改。点击「确认分镜并生成视频」时若缺标题或标签，前端先以 `fillMissing=true` 自动补全；补全失败时询问用户是否跳过，确认后继续检查与提交，标题标签可在成片后再生成或手动填写。补全请求结果待核实时，后续文案检查仍按创作记录规则被阻止。审核与标题标签沿用原计量方式（本地按用量计量），只增加回执与幂等。

同一用户在所有草稿上同时进行的文案类请求（文案、分镜、审核、标题标签）最多 2 个（`MAX_RUNNING_TEXT_OPERATIONS`，在用户级锁内计数，超过 360 秒的 running 记录不计入），超出返回 429。`/copy`、`/:id/storyboard`、`/:id/review`、`/:id/publication` 都在 `server/index.ts` 的用户级限流表中。


- `core/marketing-video` 保存共享 schema、口播长度估算、分段规划和存储接口。
- `/api/marketing-videos` 为独立项目 API，沿用会话登录和用户凭证；文案/分镜初次创作由上游处理余额，其他制作请求保留既有额度检查。模型固定在服务端；输入素材只接受当前用户资产 ID，不接受客户端任意 URL。新项目不创建聊天会话，旧会话结果继续可读。
- 迁移 36 增加 `marketing_video_projects`、`marketing_video_segments` 和 `usage_logs.idempotency_key`。草稿版本防止多页面覆盖；提交后制作配置固定，标题标签仍可修改。数据库 JSONB 比较须经过 schema 规范化，不能直接依赖键顺序。
- 草稿自动保存；浏览器仅按用户 ID 保存最后打开的项目 ID。`GET /api/marketing-videos?limit=&cursor=&q=` 按更新时间倒序分页（默认 20 条、最多 50 条），返回 `nextCursor`；游标保存 PG 原始时间戳文本和 ID，相同时间戳也不重复或漏行。`q` 按主题、发布标题、正文和标签做不区分大小写的包含匹配，`%` / `_` 按字面处理。草稿区提供搜索框和「加载更多草稿」；上次打开的草稿不在第一页时也会直接打开，已删除则忘记。断开页面不取消后台任务。
- 草稿卡片右上角可删除（`DELETE /api/marketing-videos/:id`），确认后在一个事务中删除项目、分段关联和创作记录；生成中、取消后仍在收尾、或有进行中 / 待核实的文案创作与参考分析时返回 409。删除不移除输入素材和已生成视频，二者仍在「个人素材」，需用户另行永久删除。
- PG 事务先持久化父任务、全部片段和不可变参数，再向 BullMQ 投递父任务 ID。Redis 故障后可在结果页点「重新排队」。不会自动重试付费提交。
- Worker 持有父任务 advisory lock，最多并行执行 `MARKETING_VIDEO_SEGMENT_CONCURRENCY` 个片段（默认 2，取值 1–15，不超过该视频的片段数）。成功片段继续复用；已取得模型任务 ID 的片段继续查询 / 下载。模型明确失败或产物缺少音轨、时长不足时，用户点击继续才创建新生成请求。
- 在模型 POST 前记录提交未知标记。收到任务 ID 后立即保存；未收到回执时，保留未知状态并停止再次 POST，系统不会自动清除标记重发。供应商明确拒绝创建（真人参考图，或 HTTP 400/401/402/403/404/413/422/429）或连接阶段即失败（`CONNECT_ERROR`：连接被拒、DNS 失败、连接超时、证书错误，请求未写出）时未创建任务，Worker 释放该片段的未知标记，用户修正原因后可显式继续；408/409、5xx、连接建立后的传输错误、请求超时和无效响应仍按未知处理（`run.ts → definiteRejection`）。确实未知的片段由用户确认“可能重复计费”后点击「重新提交未知片段」：`POST /:id/unknown-segments/release` 在父任务锁下只把这些片段改为可提交，并在 `marketing_video_segments.unknown_released_count / unknown_released_at`（迁移 49）记录；随后同一任务继续生成，已完成和已知供应商任务的片段继续复用。
- 片段资产与恢复输出同一事务提交；计量用用户、片段、模型任务 ID 去重，避免工作进程重启造成重复计量。重新生成失败片段可能产生供应商费用。纯查询、下载和拼接恢复不做新增额度预检。
- 制作中页面每 2.5 秒请求 `GET /:id/status`（只读一行任务状态，不解析草稿、不查素材、不签发链接），状态不变时间隔逐步放大到 15 秒，标签页隐藏时暂停、重新显示时立即查询（`session.ts → useTaskPolling`）。打开草稿时才读取完整项目。
- Worker 失败时把原因码与错误文字一起写入 `tasks.error_code`（迁移 51）：`run.ts` 抛出带码的 `MarketingRunError`，其余错误由 `marketing-video/failure.ts` 按错误类型、供应商错误码、阶段和 HTTP 状态归类，不读错误文字；队列 `setTaskError` 原样存储。码表见 `core/marketing-video` 的 `MARKETING_FAILURE_CODES`。
- 结果页由 `TaskStatus.tsx` 展示进度；停止后由 `web/.../failure.ts` 按 `errorCode` 给出「原因 + 下一步」（迁移前的旧任务没有码，显示通用指引），只给出可行操作：继续生成（同一任务，复用已完成片段）、复制为新草稿重新制作（冻结配置无法成功时，真人图片跳到素材步骤）或重新提交未知片段（按项目的 `unknownSegments` 计数判断，不依赖错误文字；确认后执行，同时展开任务编号与错误详情供核对费用）。合成阶段失败提示可直接重新合成，取消前需确认。
- 取消会传递到片段轮询、下载和 FFmpeg；第三方已接受的请求不保证可撤销或退费。原 Worker 收尾期间不允许重新激活父任务。
- 入库将视频原件、口播、发布标题、话题标签和项目 ID 保存在私有知识库。重复入库复用资料；修改标题标签后可点「更新知识库草稿」。删除过的归档可重新创建。需要 `KNOWLEDGE_MANAGEMENT_ENABLED=1`；可选索引仍遵循既有知识 Worker 开关。

首版尚无真实抖音授权和发布接口。结果页提供下载视频、复制标题标签，直发按钮明确禁用。接入后应复用持久化项目和发布元数据，另建发布任务并校验平台授权，不能把打开抖音网页视为发布成功。

## 素材访问与队列隔离

新营销上传在落库时标记为私有。迁移 47 保护旧项目和冻结任务引用的上传素材。未携带所有者会话或有效临时令牌的请求返回 404。移除素材不会恢复公开访问。浏览器预览失败时经所有者接口重新取链接。Worker 只在新提交时签发链接；已有供应商任务继续查询原 ID。音色请求在本地素材准备成功后才保存意图，已有回执仍可恢复。

营销父任务使用 `lot-marketing-video`，普通任务使用 `lot-tasks`，仍由同一个 Worker 进程启动。普通队列并发 1；营销队列每个 Worker 进程并发 `MARKETING_VIDEO_CONCURRENCY`（默认 2），每个用户在所有 Worker 上同时制作的视频不超过 `MARKETING_VIDEO_USER_CONCURRENCY`（默认 1），两者取值 1–16，非法值启动即报错。领取时 `claimTaskWithinOwnerLimit` 在用户级 advisory lock 内统计该用户仍在 BullMQ active 列表中的 running 任务，未超限才置为 running；孤立的 running 行不占名额。超限的任务保持 pending、stage 为“排队中：同账号已有视频在制作”，以 BullMQ delayed 让出槽位，15–20 秒后再试，不计为失败、不消耗尝试次数，可正常取消。首次领取时日志输出 `[queue] marketing render started` 及 `waitMs`（自入队起），用于统计排队 P95。每条视频内部同时提交的片段数为 `MARKETING_VIDEO_SEGMENT_CONCURRENCY`（默认 2，取值 1–15，仅 Worker 读取）。因此单进程同时最多有 `CONCURRENCY × SEGMENT_CONCURRENCY` 个片段请求（默认 4）和 `CONCURRENCY` 个合成。例如允许 2 个用户各自的视频同时提交 4 个片段：`MARKETING_VIDEO_CONCURRENCY=2`、`MARKETING_VIDEO_USER_CONCURRENCY=1`、`MARKETING_VIDEO_SEGMENT_CONCURRENCY=4`，共 8 个片段请求。提高并发前先确认供应商并发限额，并按排队 P95 和内存评估。该配置与参考视频分析的 `MARKETING_ANALYSIS_CONCURRENCY` 无关。旧队列作业保留原 ID 转发；旧 active 作业不会重复投递。取消、显式恢复和未启动任务超时保护覆盖两个队列。该改动隔离消费槽位，不等于主机资源隔离。

升级前停止新提交，并等待已使用旧无签名素材地址的供应商任务完成。停止旧 Worker 后执行迁移至 47，再启动同版本服务。不要混跑仍提供匿名素材访问的旧 API。具体步骤见下方“升级和发布验收”。

### 私有素材与兼容边界

营销上传使用 `purpose=marketing-video`，缺少签名密钥时在写文件前返回 503。迁移 0047 扫描项目及父任务冻结草稿中的单个 ID、数组和大写 UUID，仅保护归属一致的上传资产，不重写素材 ID、冻结输入或供应商回执。之后把普通上传用于营销草稿也会转为私有，移除引用不会恢复公开。

临时令牌绑定素材 ID、所有者、存储键和用途，有效期 10 分钟；响应 `private, no-store`，合法 Range 返回 206。无登录/令牌、跨用户、过期/篡改令牌、归属变化、无资产记录或数据库失败均返回 404。预览失败后每素材每分钟至多重取一次链接，不保存草稿或调用模型。图片和视频链接在音色准备完成后重新签发，令牌不进入任务输入、缓存身份和音色指纹。

生成成片、生成图片及显式分享不因此改为私有；已不被任何草稿或冻结任务引用的历史上传无法自动判定营销用途，外部已保存的旧副本也无法撤回。Hono 不记录素材路径，Nginx `/static/uploads/` 关闭访问日志、错误日志和代理缓存；外层 CDN / 网关需保持相同约束。

迁移 0046 只更新父任务队列元数据。旧 waiting 作业保留原 ID 转发，active 不重复投递，锁竞争停止迁移，终态不自动重跑。取消和恢复检查两条队列。三分钟未领取只触发诊断，健康等待或 Redis 未知不能写成失败；后续队列与取消契约见[实施记录](marketing-video-implementation-20261016.md)。

合成就绪检查（`media.ts → mediaCapabilities`）不再只执行 `-version`：先确认 `libx264`、`aac` 编码器和合成所需滤镜（scale、pad、setsar、fps、aresample、apad、anullsrc、amix、volume、asplit、color），再按真实流程编码一段 0.4 秒探针片段、用 concat 拼接并 ffprobe 读回。结果按二进制路径和版本缓存 10 分钟，失败不缓存。API 在 `/generate` 前检查；Worker 在准备音色和提交任何片段前再检查一次本机，失败即停止，不产生费用。

已有视频任务 ID 只查询/下载，成功片段复用原资产；音色 unknown 只查询原外部请求 ID，新音色授权或签名失败不写请求意图，并发仅 claim 胜者提交。计量键保留 `marketing:<片段任务 ID>:<供应商任务 ID>`。历史 WebM 可读取、移除或替换，新生成仍执行当前素材规则；Worker 按任务冻结的 `generate_audio` 恢复旧任务。

### 审核与修订行为

语义模型接收结构化字段及上述规则，输出精确字段、分镜序号、原文片段、风险原因、替换建议、严重度与规则来源。服务端严格校验来源分类、字段位置和原文是否真实存在，拒绝缺少定位、无效分镜、虚构原文及结论矛盾的结果；再合并本地确定性条件规则，模型的空 `pass` 不能忽略本地已发现风险。

白名单仅对相关词的局部语义有效，不能放行整句或全文中的其他风险。否定和科普同样检查词所在的局部上下文；“不是骗局，这个投资项目必赚”仍会提示。专利号、特证、检测报告、榜单、医生协议等文本本身不能验证资质真实性和适用范围，相关内容保留“待核实”。原表的替换示例可能继续构成功效、收入或事实承诺，默认改为删除承诺或客观中性表达。

每条问题精确定位到一个字段。安全替换仅作用于该字段中唯一、完全匹配的片段；片段缺失、重复、超长或跨分镜时拒绝猜测替换。分镜台词修改同时更新总文案；总文案可安全映射到单个分镜时同步该镜头，手动重写总文案会清除旧分镜以避免口播不一致。修改后前端保存并重新检查，未使用替换结果充当审查通过。

`marketingReviewText()` 是包含版本和字段边界的审核指纹，覆盖总文案、分镜台词与全部画面描述。任一审核内容或规则版本变化都使旧结论失效；旧版遗漏台词或背景的结果也需重新检查。超过可完整呈现的 80 条问题时返回检查未完成，避免静默丢弃后续高风险问题。

## 环境和验证

先由 API 执行迁移，再启动 Worker。API 和普通视频 Worker 均需要 `ffmpeg`、`ffprobe`；编码需要 libx264、AAC；模型字幕不依赖 libass 或本地字幕字体。可用 `MARKETING_FFMPEG_PATH` / `MARKETING_FFPROBE_PATH` 指定程序路径。容器配置参见 [部署](deployment.md)。拼接能力检查失败时界面阻止生成；字幕选项仅控制模型提示词，不参与本地能力检查。

音色样例继续使用 `KLING_VOICE_BASE_URL` / `KLING_VOICE_API_KEY`，视频推理仍使用当前用户模型凭证；素材引用需要正确的 `PUBLIC_BASE_URL`。营销上传素材为私有，API 和 Worker 必须使用相同的现有 `SECRET_MASTER_KEY`。浏览器和供应商使用有效期 10 分钟的临时链接。未选择音色样例时使用模型原生旁白。

页面先检查草稿列表和服务能力，成功后才启用编辑、自动保存和生成；接口未部署返回 404 时显示更新服务提示，连接失败可点「重新连接」。普通本地开发代理连接 `localhost:3000`，仅桌面开发模式跟随桌面服务器设置。线上升级必须同时更新 Web、API、Worker 和 Nginx 配置，并执行迁移至 49（49 增加未知结果的放弃记录）；只更新 Web 会导致新接口 `Not Found`。文案和分镜生成后自动保存；风险检查可按需执行，提交制作前仍会自动检查当前内容。

## 后续对口型服务候选

| 服务 | 对本项目的用途与限制 |
| --- | --- |
| [腾讯云智能数智人：视频免训练](https://cloud.tencent.com/document/product/1240/116222) / [照片免训练](https://cloud.tencent.com/document/product/1240/118475) | 优先评估需要同时覆盖实拍与数字人的方案。视频和照片都有文本 / 音频驱动接口；照片音频驱动支持 2–60 秒，输出 720p / 1080p。视频接口需购买小时包或并发资源；应先用同一文案和素材对比实际效果。 |
| [阿里云 VideoRetalk](https://help.aliyun.com/en/model-studio/videoretalk-api) | 适合先补实拍口型替换。输入人物视频及完整人声音频；视频 / 音频均支持 2–120 秒，可覆盖本项目长度。北京地域，需单独接入完整 TTS 音轨；现有 Kling 参考音色不等同于输出的配音文件。 |
| [阿里云 wan2.2-s2v](https://help.aliyun.com/zh/model-studio/wan-s2v-api) | 照片 + 音频驱动的另一选择，480p / 720p；单段音频须小于 20 秒，仍需复用本项目的分段和拼接。 |

建议先评测腾讯两类免训练接口是否能统一满足素材路径；若只补实拍口型，优先小规模评测 VideoRetalk。后续链路应先生成完整 TTS 音频，再以音频驱动人物并获得字幕时间轴，最后混 BGM；这会比当前模型原生配音更便于控制文案和字幕。
